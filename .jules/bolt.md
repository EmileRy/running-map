## 2026-06-26 - Pre-calculating timestamps for O(1) filtering
**Learning:** Parsing ISO date strings (`new Date()`) inside a tight render loop (like a slider interaction) is a significant bottleneck when dealing with thousands of tracks. React 19 and Next 16 enforce strict purity and linting (e.g., `react-hooks/purity` and `react-hooks/set-state-in-effect`), which requires careful handling of side effects and impure functions like `Date.now()`. Deferring state updates with `setTimeout` and using `useSyncExternalStore` for hydration-safe mounting are effective patterns for satisfying these constraints.

**Action:** Always pre-calculate derived numeric data (like timestamps) on the server in Server Components before passing them to interactive client components. Use centralized type definitions in `frontend/types/` to maintain consistency across the data fetching and rendering layers. For React 19 purity, provide stable 'now' values via module-level constants or specialized hooks like `useMountNow`.
